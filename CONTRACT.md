# suitediet contract

This contract is the executable spec for suitediet. Every obligation below maps to at least one named test in the test suite. An obligation is met only when its tests pass.

## Ground and probes

Cantfail asks whether a test can fail, suitediet asks which tests earn their runtime. Suitediet is the deletion half of suite care with holdout discipline. It ranks tests by measured value, proposes a cut line, and ships every removal with the evidence that the suite still catches what the removed test caught. It reads local files only and never reaches a network in the tool or in its tests, and it deletes nothing.

The record ground is suitediet's own. A measured record set stands in one document whose format name is suitediet-records/1. The document carries a suite name and a tests list, and each test record carries a name and a runtime in whole milliseconds and the list of defect identifiers the test caught. A defect identifier names one planted or mutated defect, and a test's caught list is the per test reading of a catch record, so the defects a test caught and the tests that caught a defect are two readings of the same evidence. A front end that turns a raw canaryfield catch table or a mutation run into records is later work and is stated here as a limit rather than built silently into this slice. The reader holds the records it reads in a normalised form, with the tests sorted by name and each caught list sorted, and that normalised form is the canonical written form of a record set. A record carried into a removal pack or a quarantine record or a restore is the record exactly as the reader holds it, and the words exactly as read in the obligations below mean the record in that held form.

The parsing probes ran on synthetic documents in this repo's scratch and are recorded here because the obligations rest on them. The first probe listed one test name twice in a records document and the parser returned both records without complaint, so a duplicated test name survives parsing and uniqueness is the reader's own obligation. The second probe listed one defect identifier twice inside a single caught list and the list came back with the duplicate standing, so that uniqueness is also the reader's obligation. The third probe added float seconds and found that 0.1 and 0.2 sum to 0.30000000000000004 rather than to 0.3, while whole milliseconds add exactly, so runtime stands in whole milliseconds in every record and every total. The fourth probe summed three shares of one third as exact rationals and reached exactly one by construction, so every share and every value in the ranking is an exact rational and never a float. A fifth probe wrote one key twice inside a single JSON object and the parser kept the second value and dropped the first without a word, so a repeated key never reaches the reader as two fields standing side by side, and refusing it is the reader's own obligation at parse time.

The overlap probe is the load bearing one. Its shape was one defect caught by exactly two tests, both standing below the cut line. A naive per test reading asks whether any other test catches the defect, finds one for each test, and clears both, and afterwards nothing catches the defect. The sequential reading decides the worst test first against the set of tests still standing, clears that one while its fellow still stands, and then finds the fellow blocked, because its only other catcher is already removed. The removal obligations below follow the sequential reading, and the naive reading is named here so no later slice reintroduces it as a shortcut.

The value ground is stated here and carried into an obligation below. A defect counts in full to a test that catches it alone and counts divided among its catchers when several tests catch it, so a test's weighted catches are the sum over its defects of one divided by the number of catchers of each defect. A test's value is its weighted catches divided by its runtime, which reads as earned catches per millisecond. Runtime is the cost and weighted catches are the earning, and the ranking compares exact rational values even where the printed rendering of two values agrees.

The cut line ground is a runtime budget. The plan takes a budget in whole milliseconds and keeps the longest prefix of the ranking whose combined runtime fits inside it, and every test after that prefix stands below the line. A removal is only ever proposed from below the line, and a test below the line whose removal would lose a catch is not proposed at all. Its block is printed in its removal pack and it stays in the suite.

The quarantine ground is the safety half of the tool. A proposed removal moves the test into a quarantine record that carries the test's full record, and nothing is deleted. A restore path reads the record set that remained and the quarantine record and returns the suite record exactly as it stood before the plan, so a diet can be undone whole. Deletion after quarantine is a human act outside this tool.

## Slice 2 obligations

Obligation SD2-1 covers records reading. The reader accepts one document whose format name is suitediet-records/1 and whose fields are exactly the format name and the suite name and the tests list, and each test record carries exactly a name and a runtime and a caught list. A missing field or an unexpected field or a wrong format name or an empty tests list is refused with a suitediet error rather than guessed. A duplicated test name is refused, and a defect identifier duplicated inside one test's caught list is refused, and a runtime that is not a positive whole number of milliseconds is refused, and a name or a defect identifier that is empty or not text is refused. Proven by test_records_document_is_read_exactly and test_records_with_a_missing_or_unexpected_field_are_refused and test_wrong_format_name_is_refused and test_an_empty_tests_list_is_refused and test_duplicate_test_names_are_refused and test_a_duplicate_defect_within_one_test_is_refused and test_a_non_positive_runtime_is_refused.

Obligation SD2-2 covers the derived catchers. The catchers of a defect are exactly the tests whose caught list names it, derived from the records alone with no second input, and the catchers of every defect together account for every caught entry in every record. Proven by test_catchers_are_derived_from_the_records_alone.

Obligation SD2-3 covers the value rule. A defect caught by one test alone contributes one to that test's weighted catches, and a defect caught by several tests contributes one divided by the count of its catchers to each of them, and a test that catches nothing holds weighted catches of zero. A test's value is its weighted catches divided by its runtime in milliseconds, compared as an exact rational. Proven by test_a_defect_counts_in_full_to_its_only_catcher and test_a_shared_defect_counts_divided_among_its_catchers and test_value_is_weighted_catches_per_millisecond.

Obligation SD2-4 covers the ranking. Tests are ordered by value descending and then by weighted catches descending and then by runtime ascending and then by name ascending, and that order is total and deterministic. Two tests holding identical records are ordered by name. The comparison uses the exact rational values, so two tests whose printed values agree still order by their exact values. Proven by test_ranking_follows_the_stated_tie_rule and test_identical_records_rank_by_name and test_ranking_uses_exact_values_not_the_rendered_ones.

Obligation SD2-5 covers the cut line. Given a budget in whole milliseconds the survivors are the longest prefix of the ranking whose combined runtime fits inside the budget, and every later test stands below the line. A budget smaller than the best test's runtime cuts every test, and a budget covering the whole suite cuts nothing, and a budget that is not a positive whole number is refused. Proven by test_the_cut_line_keeps_the_longest_prefix_that_fits_the_budget and test_a_budget_below_the_best_test_cuts_every_test and test_a_budget_covering_the_whole_suite_cuts_nothing and test_a_non_positive_budget_is_refused.

Obligation SD2-6 covers the unique catch block. Removals are decided from below the line, worst first, against the set of tests still standing. A defect blocks a test's removal when every catcher of that defect is either the test itself or a test already cleared for removal, and a test holding any blocking defect is not proposed for removal and stays in the suite, whatever its value. A test holding no blocking defect is clear to propose. A test that catches nothing is clear whenever it stands below the line. Proven by test_a_unique_catch_blocks_removal_even_at_the_lowest_value and test_a_test_with_no_unique_catches_is_clear_to_propose and test_a_test_that_catches_nothing_is_clear_when_below_the_line.

Obligation SD2-7 covers the shared cover conjunction. Where two tests below the line are each other's only other catcher of a defect, the worse of the two is cleared while its fellow still stands and the better of the two is then blocked, and after the plan the defect is still caught. The decision order is worst first and is part of the reading, so the same records under the same budget always split the pair the same way. Proven by test_two_tests_that_only_cover_each_other_split_clear_and_blocked.

Obligation SD2-8 covers the removal packs. Every test below the line carries one removal pack, listed in the order the decisions were taken. A pack carries the test's full record exactly as read and its rank and its weighted catches and its value and its disposition, which is quarantine for a cleared test and blocked for a held test. A pack states the overlap exactly, naming for each defect the test caught the tests still standing after the whole plan that also catch it, and a blocked pack names every blocking defect in full. Proven by test_a_removal_pack_carries_the_record_and_the_exact_overlap and test_a_blocked_pack_names_every_blocking_defect.

Obligation SD2-9 covers the diet totals. The report counts the distinct defects the whole suite catches before the plan and the distinct defects the suite still catches after the proposed removals, and both counts are computed from the sets themselves and never copied from one another. The defects a plan loses are the before set minus the after set, computed and printed, and a plan built under the block rule loses none. A blocked test stays in the suite, so a defect it uniquely catches still counts after. Proven by test_totals_count_the_catches_before_and_after and test_the_after_total_never_claims_a_catch_the_plan_loses.

Obligation SD2-10 covers quarantine and restore. The quarantine record carries the full record of every cleared test and of no other test, in the format suitediet-quarantine/1, and a blocked test never enters it. The record set that remains holds the survivors and the blocked tests. Restoring reads the remaining record set and the quarantine record and returns the suite record set exactly as it stood before the plan, byte for byte in the canonical written form, and refuses a quarantine record whose suite name disagrees or whose tests collide with tests still standing. Proven by test_quarantine_carries_only_the_cleared_tests_with_their_full_records and test_a_blocked_test_never_enters_quarantine and test_restore_returns_the_suite_record_exactly and test_restore_refuses_a_quarantine_that_disagrees.

Obligation SD2-11 covers deterministic output and the offline boundary. Every written document uses sorted keys and two space indentation and one trailing newline and carries no wall clock time and no local filesystem path, and running either command twice on the same inputs produces byte identical bytes. The tool reads only the local files named on its command line and a missing local input is refused with a suitediet error, and the test suite builds every fixture synthetically and uses no network. The committed examples regenerate byte identically from their committed inputs. Proven by test_cli_writes_deterministic_outputs and test_missing_inputs_are_refused and test_outputs_carry_no_local_paths and test_committed_examples_regenerate_byte_identical.

## Round 1 review fixes

The Round 1 red team and the two axis review each returned conditional, and the obligations below answer their findings. The red team's Major and the spec axis's Major are one defect, a diet that empties the suite cannot be undone, and the remaining findings are one Minor from the red team and one Minor and two Notes from the standards axis. The obligations below amend SD2-1 and SD2-5 and SD2-8 and SD2-10 where they conflict, and each one is covered by the tests of the Round 1 fix file unless it says otherwise. Two record repairs ride with them and carry no obligation. The README status gains the standing closed round line at zero of 100, which the agent instructions already promised and the status section lacked, and the README wording for the removal pack overlap now matches what SD2-8 computes, the tests still standing after the whole plan, survivors and blocked tests alike, rather than the survivors alone.

Obligation FIX-1 covers restoring a diet that clears every test. A plan whose budget clears every test writes a remaining record set carrying an empty tests list, and that empty list is a true reading of an emptied suite rather than a malformed document. The restore command reads the remaining record set through a reading that accepts the empty tests list, while the refusal of an empty tests list in SD2-1 stands unchanged for the records document the plan command reads. Restoring such a remaining set with its quarantine record returns the suite record set exactly as it stood before the plan. Proven by test_restore_undoes_a_plan_that_cleared_every_test.

Obligation FIX-2 covers a repeated key inside a JSON object. The parser keeps the second value of a repeated key and drops the first without a word, so a document as written can carry a field the reader never sees, and a wrong format name can hide behind a second format key naming the right one. A JSON object carrying one key twice is refused at read time, at the document level and at the record level and in the quarantine record alike, so the exact reading of SD2-1 holds for the document as written and not only for the document as parsed. Proven by test_a_repeated_document_key_is_refused and test_a_repeated_record_key_is_refused and test_a_repeated_format_key_cannot_hide_a_wrong_format_name.

Obligation FIX-3 covers the budget argument at the command line. A budget argument that is not a whole number is refused with a suitediet error and a clean nonzero exit and writes nothing, the refusal discipline the rest of the tool keeps, rather than dying inside the argument parser with a usage dump. A budget that parses as a whole number still reaches the refusal of SD2-5 when it is not positive. Proven by test_a_non_whole_number_budget_is_refused_at_the_command_line.

Obligation FIX-4 covers the markdown rendering of a removal pack. The markdown states the per defect overlap the JSON pack carries, naming for each defect the test caught the tests still standing after the whole plan that also catch it, and stating where no other test still standing catches it, so a reader of the markdown sees the same overlap evidence the JSON states. Proven by test_the_markdown_report_states_the_pack_overlap.
